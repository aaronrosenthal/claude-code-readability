# Configuration

The plugin works without configuration. Configuration exists for projects whose conventions differ from the defaults.

## Where configuration lives

| Source | Location | Precedence |
| :- | :- | :- |
| Built-in defaults | `src/config/config.mjs` | lowest |
| User file | `~/.claude/readability.json` (or `$CLAUDE_CONFIG_DIR/readability.json`, or `READABILITY_USER_CONFIG`) | |
| Project file | `.readability.json` or `.claude/readability.json` at the project root | |
| Environment | `READABILITY_MODE`, `READABILITY_FEEDBACK` | highest |

Later sources override earlier ones key by key; nested sections (`exceptions`, `suppressions`, `documentation`, ...) merge
field by field, arrays are replaced. **A project file overrides your user file**, so a repository's conventions win over
personal preferences. Use the environment variables for a one-off session (`READABILITY_MODE=advisory claude`).

Invalid files or values are ignored with a warning (visible with `READABILITY_DEBUG=1`), never fatal. A JSON Schema is
published at [`schema/readability.schema.json`](../schema/readability.schema.json):

```json
{ "$schema": "https://raw.githubusercontent.com/aaronrosenthal/claude-code-readability/main/schema/readability.schema.json" }
```

The project root is `CLAUDE_PROJECT_DIR` (or the session's working directory) when the edited file is inside it,
otherwise the nearest enclosing git repository, otherwise the file's directory.

## Modes

| Mode | New unnecessary comments | New suppressions | External references |
| :- | :- | :- | :- |
| `strict` | rejected unless tagged, required by a linter, or allowed by config | rejected unless listed in `suppressions.allow` | rejected unless tagged |
| `balanced` (default) | rejected | allowed when specific, narrow, and justified | allowed |
| `advisory` | reported to Claude as context, never blocked | reported | allowed |
| `off` | not checked | not checked | |

## Example

```json
{
  "mode": "balanced",
  "exclude": ["scripts/one-off/**", "**/*.sql"],
  "languages": {
    "python": { "mode": "strict" },
    "sql": { "mode": "off" }
  },
  "documentation": { "module": "auto", "class": "auto", "function": "auto", "method": "auto", "property": "auto" },
  "exceptions": { "tags": ["SAFETY", "SECURITY", "INVARIANT", "COMPAT", "WORKAROUND", "CONSTRAINT", "HISTORY", "LEGAL", "PERF"], "minWords": 4 },
  "directives": {
    "custom": [{ "name": "licensecheck", "pattern": "^licensecheck:(?:skip|ok)$", "kind": "pragma" }],
    "optional": ["xcode-mark"]
  },
  "suppressions": {
    "new": "auto",
    "requireJustification": true,
    "allowBlanket": false,
    "allowFileWide": false,
    "allow": { "eslint": ["no-console"], "ruff": ["T201"] },
    "deny": { "typescript": ["*"], "*": ["*docstring*"] }
  },
  "discovery": { "enabled": true },
  "retryLimit": 3,
  "protectConfigFiles": true
}
```

### `exclude`, `useDefaultExcludes`

Path globs relative to the project root (`**`, `*`, `?`, `{a,b}`; a pattern without `/` matches at any depth). By default
dependency, vendored, and generated paths are skipped: `node_modules`, `vendor`, `third_party`, `Pods`, `__generated__`,
minified bundles, `*.generated.*`, `*.g.dart`, `*.pb.go`, `*_pb2.py`, `*.designer.cs`, plus any file whose header carries
a `Code generated ... DO NOT EDIT.`, `@generated`, or `<auto-generated>` marker.

### `languages`

Overrides keyed by language id (`typescript`, `tsx`, `python`, `go`, ...; see [directives.md](directives.md)) or family
(`javascript` covers JS/TS/JSX/TSX, `c` covers C and C++ ...). Values accept the same keys as the top level.

### `documentation`

Per declaration kind (`module`, `class`, `function`, `method`, `property`):

- `auto` (default): documentation required by a discovered linter rule is always allowed. Otherwise, in balanced mode,
  documentation on public declarations is allowed unless it merely restates the declaration (`/** Gets the user name. */`
  on `getUserName`); documentation on private helpers is rejected. Strict mode rejects documentation that nothing requires.
- `allow`: always allow documentation for this kind.
- `restrict`: allow it only when a linter requires it or it carries an exception tag.

Machine-read type annotations (JSDoc `@type`/`@typedef`, PHPDoc `@var`/`@param` types, ...) are directives and always allowed.

### `exceptions`

Comments that start with an exception tag (`SAFETY:`, `SECURITY:`, `INVARIANT:`, `CONCURRENCY:`, `COMPAT:`,
`WORKAROUND:`, `CONSTRAINT:`, `HISTORY:`, `LEGAL:` by default) are accepted when they have at least `minWords` words of
substance. `allowExternalReferences` (default: true except in strict mode) accepts comments that link an issue,
specification, CVE, or RFC. `allowLicenseHeaders` accepts license and copyright text in the file header.

TODO, FIXME, HACK, XXX, and NOTE are deliberately **not** exceptions.

### `directives`

- `custom`: project-specific machine-read comments. `pattern` is a regular expression tested against the comment body
  (the text after the comment marker). `kind: "suppression"` puts the directive through the suppression policy.
- `optional`: opt-in built-in sets that some teams treat as navigation rather than prose: `xcode-mark` (`// MARK: - ...`)
  and `vscode-region` (`#region` / `#endregion`).

### `suppressions`

Policy for **new** linter suppressions. Existing suppressions are never reported unless an edit broadens them.

- `new`: `auto` (strict → `deny`, balanced → `justify`, advisory → `allow`), `justify`, `deny`, or `allow`.
- `requireJustification`: a reason of at least three words, using the tool's own syntax (ESLint `-- reason`, Biome
  `: reason`, golangci-lint `// reason`, ...) or a comment directly above the suppression.
- `allowBlanket`: allow suppressions that name no rule (`# noqa`, `// eslint-disable-next-line`).
- `allowFileWide`: allow file-scoped suppressions, including region suppressions that are never closed.
- `allow` / `deny`: maps from tool key to rule globs. `allow` entries are accepted in every mode; `deny` entries are
  always rejected. Tool keys: `bandit`, `biome`, `checkstyle`, `clang-tidy`, `c-tools`, `coverage`, `credo`, `dart`,
  `eslint`, `flow`, `golangci-lint`, `hadolint`, `iac`, `intellij`, `lintr`, `luacheck`, `markup`, `mypy`, `php`, `pmd`,
  `prettier`, `pylint`, `resharper`, `rubocop`, `ruff`, `shellcheck`, `sonar`, `sqlfluff`, `stylelint`, `swiftlint`,
  `typescript`, `yamllint`, and `*` for any tool.

Suppressing a **documentation rule** (for example `Style/Documentation`, `D103`, `missing-function-docstring`,
`jsdoc/require-jsdoc`, `CS1591`, `MissingJavadocMethod`, `missing_docs`) is always rejected unless that rule is
explicitly allowlisted, whether it is written as a comment, a Rust/Java/Kotlin attribute, or a C# pragma.

### `discovery`

When enabled (default), the hook reads (never executes) linter configuration to learn whether the project requires
documentation. See [discovery.md](discovery.md).

### `retryLimit`

After the same comments are rejected more than `retryLimit` times in a session (or the same file more than twice that),
the hook lets the edit through and tells Claude to mention the remaining comments to you. This prevents loops.

### `protectConfigFiles`

When true (default), edits to the readability configuration, and edits to linter configuration that weaken a discovered
documentation requirement, are turned into a permission prompt (`ask`) instead of being applied silently.

## Environment variables

| Variable | Effect |
| :- | :- |
| `READABILITY_MODE` | Overrides `mode` |
| `READABILITY_FEEDBACK` | `actionable` (default) or `minimal` |
| `READABILITY_USER_CONFIG` | Path of the user configuration file |
| `READABILITY_DEBUG` | Print the hook's decision trace and any internal error to stderr |
