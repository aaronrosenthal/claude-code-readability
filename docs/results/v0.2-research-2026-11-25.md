# Research suite results for v0.2.0, 2026-11-25

Plugin at commit `eaf9370`, which became v0.2.0:
- the skill now asks for comments that explain *why* the code is written the way it is;
- the hook defaults to `advisory` mode, which warns instead of blocking.

Model under test: `claude-sonnet-5-5`. Arms A (no plugin), B (skill only), and D (full plugin in its default mode). Arm
C (blocking hook without the skill) was not rerun because nothing in it changed. Each of the 45 cases ran twice per
arm, for 270 valid runs. Agent cost was $25.95 at list price. The blinded pairwise judge (`claude-sonnet-5-5`, A vs D
and B vs D) and the comment audit cost $14.02. Generated by `evals/tools/analyze.mjs`. Raw transcripts are not
published.

How to read this page:

- **The results were merged from several invocations.** In the first invocation, 191 runs hit the 5-hour usage limit
  and were discarded. They were rerun the next morning: A and D for the 26 cases with missing runs, and B for all 45
  cases. Within each case and arm, both runs come from the same invocation. Because B ran on a different day from most
  of the A and D runs, B-vs-D differences may include day-to-day variation.
- **The 0.1.x results are in [research-2026-11-24.md](research-2026-11-24.md).** They used the same cases, model, and
  harness, so the two pages can be compared directly.
- **The skill change was tested on 18 of these cases before this run.** That earlier test cost $16.11 and is not
  reported separately. The skill was rewritten in general terms, with an example from a domain none of the cases use.
  Even so, the cases that prompted the change are part of this suite.

## Summary

- **The main problem from 0.1.x is gone.** With comments visible, the judge now slightly prefers the plugin's code
  (56%). Under 0.1.x it preferred the code written without the plugin (37%). The interval still includes 50%. The fair
  claim is that the plugin no longer costs useful comments, not that comments make its code better.
- **The structural gains held.** With comments removed, D still wins on readability (73%) and on identifiers (49 of
  49). Complexity is about 3.6 lower per case [−5.5, −2.1]. Correctness is 100% in all arms.
- **D keeps more comments, and more of them are worth keeping.** D writes 2.5 new comment lines per run, A writes 3.0,
  and D under 0.1.x wrote 2.0. The audit judged 15% of D's surviving comments unnecessary, against 19% for A.
- **The hook adds nothing measurable over the skill alone.** B vs D:

  | Comparison | D preferred |
  | :- | -: |
  | Maintainability, comments visible | 47% [34%, 60%] (even) |
  | Readability, comments removed | 34% [21%, 51%] |
  | Control flow, comments removed | 30% |
  | Abstraction, comments removed | 25% |

  The deterministic metrics barely differ: complexity is 11.4 for B and 10.9 for D, and new comments 2.52 and 2.54. In
  the rationales, the two candidates are often "nearly identical", and the winners differ in ordinary implementation
  choices. Because B ran a day later, this may partly be day-to-day variation. At best, the advisory hook does not
  help readability here.
- **Some advisory notes fired on useful comments.** The transcripts do not record hook context. Replaying D's 37
  `Write` calls through the hook, the advisory note fired on 10, and most of the flagged comments were reasons Claude
  then kept, for example: "Sort columns are interpolated into the SQL text, so only this allowlist may ever reach it."
  In blocking mode these would have been rejections. A separate check confirmed that Claude receives the advisory
  note.
