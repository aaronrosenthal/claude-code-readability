# Research suite results, 2026-11-24

Model under test: `claude-sonnet-5-5`, 2 runs per case per arm. 45 cases x 4 arms x 2 runs = 360 valid agent runs.
Blinded pairwise judge and comment audit: `claude-sonnet-5-5` (A vs D only). Per-run native maintainability grader:
`claude-haiku-5-5`. Agent cost was $49.27 at list price, including runs discarded for the reasons below. Judging and
the audit cost $7.25 more. Generated by `evals/tools/analyze.mjs`. Raw transcripts are not published.

How to read this page:

- **The runs used the v0.1.0 hook.** The eval found two hook bugs, both fixed in 0.1.1:
  - Python docstrings after a multi-line `def` header were rejected.
  - C#/Java `public` constructors were read as private.

  Replaying all 46 rejected edits from arms C and D through the 0.1.1 hook allows 18 of them. These 18 edits caused all
  four of arm C's correctness failures (`csharp-xml-docs-required` and `python-module-docstrings-ruff`). The row "New
  comments the hook classifier would reject" is computed with the 0.1.1 classifier.
- **The results were merged from several invocations.** Some runs failed because the eval sandbox could not read the
  toolchains, the 5-hour usage limit was reached, or the `go-webhook-client-retry` fixture bound a socket. These runs
  were discarded and rerun after the fixes. Each case and arm in the merged set comes from one invocation with the same
  model, plugin build, and settings.
- **The intervals describe this suite only.** With 2 runs per case, they describe run-to-run variation for these
  cases and this model. They are not evidence about tasks in general.

## Summary

- **Correctness held.** A 100%, B 100%, D 99% (one `csharp-obsolete-api-suppression` failure), C 96% (all four C
  failures were hook bugs, fixed in 0.1.1).
- **Structure improved with the skill.** With comments removed, the blinded judge preferred D over A on readability
  in 77% of decisive comparisons [64%, 87%]:

  | Criterion | D preferred |
  | :- | -: |
  | Identifiers | 47 of 47 |
  | Control flow | 72% |
  | Abstraction | 74% |

  Cognitive complexity fell by 3.7 per case in D [−5.5, −2.1] and by 3.4 in B, but not in C (−0.2). Revisions after
  hook rejections in C were mostly comment deletion (16 of 24). The structural gain comes from the skill, not from
  enforcement.
- **But D lost on maintainability as written.** With comments shown, the same judge preferred A in 41 of 65 decisive
  comparisons (D win rate 37% [26%, 49%]). In 39 of those 41 rationales, the judge says A kept context that D left
  out. Examples:
  - the Canada Post letter exclusions behind a postal-code regex;
  - why a `min(1.0, x)` clamp exists (floating-point drift);
  - why a timeout is enforced by `WaitAsync`.

  D wrote such comments less often, even without a rejection: its hook fired only 0.17 times per run. The skill
  discourages comments too broadly.
- **The two judges disagreed.** The per-run maintainability grader (Haiku) rated each run on its own and passed D more
  often than A (76% vs 58%; B 79%). The pairwise judge (Sonnet) compared A and D side by side and preferred A. The two
  differ in model and in method, so neither result settles the question alone.
- **The hook has many false positives.** Of the comments the v0.1.0 hook rejected, the blinded audit labeled 68% (C)
  and 53% (D) necessary. After removing runs whose rejections the 0.1.1 hook now allows, the rate is still 66%
  (37 of 56) in C and 57% (4 of 7) in D. Most of these comments state facts or constraints without causal wording, for
  example "Caller must hold the lock" or why a deprecated API is still called. Meanwhile, 18% of the comments that
  passed the hook were judged unnecessary, about the same share as in A (19%).
- **The cost is moderate.** D used about 17k more tokens per run than A [10k, 25k], took 3.6 s longer, and cost about
  $0.02 more. B was cheaper than D, with a similar effect.
- **Shell writes followed rejections, but did not smuggle comments past the hook.** Arm C wrote source files through
  the shell more often than A: 0.68 times per run, against 0.39. In 16 runs (13 in C, 3 in D), 29 shell writes came
  after a rejection. The final code of each of those runs contains no comment that the hook classifier rejects. C's
  structural graders, which check suppressions and config edits, passed slightly less often: 0.89, against 0.92 for A,
  which is within noise. Shell writes remain unchecked.
